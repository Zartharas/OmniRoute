## 8. Direct-model versus combo-path clarification

Earlier normal requests through CC Switch using the `OmniRoute — Nemotron 3 Super` profile reached the live OmniRoute `/v1/responses` path and produced NVIDIA/Nemotron routing/provider activity, but D19 remained at zero.

Source review established that this was not sufficient to claim an observer wiring defect:

- `/v1/responses` delegates to the unified `handleChat`;
- `handleChat` only invokes `handleComboChat()` when `getComboForModel(resolvedModelStr)` (or an auto/safety-net path) resolves a combo;
- otherwise the request proceeds through `handleSingleModelChat()`;
- D19-S8 inline observation is bound inside `combo.ts`.

The direct Nemotron request therefore did not establish that the combo path should have executed. Once the actual configured combo `ibm-mta-free-first` was exercised, the D19 readout populated.

Conclusion:

- CC Switch → OmniRoute ingress: confirmed;
- `/v1/responses` handling: confirmed;
- direct provider execution: confirmed;
- production combo path: confirmed using `ibm-mta-free-first`;
- D19 inline observer production wiring: confirmed.
